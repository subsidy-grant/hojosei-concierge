# Uidesign UI採点改善ループ

実ブラウザで**実際のユーザータスク**を通しながら各画面を採点し、最も弱い箇所から安全に改善する。

## 手順

1. **対象フローと完了基準を決める**（例：「診断開始→結果表示まで」「タスク登録→一覧確認まで」）。指定がなければ製品の主要フローを推奨として選ぶ。
2. **クリーンな実ブラウザで開始**：Playwright（python3、chromium同梱）で保存ログイン・Cookie・キャッシュなしの新規コンテキスト。**毎周これをやり直す**。
3. **合意サイズでスクリーンショット取得**：スマホ幅375pxとPC幅1280pxの両方。意味のある画面（初期状態・入力中・結果・エラー）をすべて撮る。
4. **統一チェックリストで各画面を採点**（各5点満点、全画面同じ基準）：
   - **視覚的階層**：最初に目が行く場所が、その画面の最重要アクションか
   - **一貫性**：色・余白・ボタン形状・用語が画面間で揃っているか
   - **可読性**：フォントサイズ・コントラスト・行間。**非IT利用者・中高年でも読めるか**（コントラスト比4.5:1目安）
   - **操作性**：タップ領域は指で押せる大きさ（44px目安）か、入力の手間は最小か、エラー時に次の行動が分かるか
   - **状態表現**：ローディング・空状態・エラー・成功がそれぞれ視覚的に分かるか
   - **キーボード・ズーム耐性**：Tab移動で操作できるか、200%ズームで崩れないか
5. **最弱点を1つ、安全な範囲で改善**する（機能・セキュリティ・既存の合格画面を壊さない最小変更）。
6. **フロー全体を再実行して再採点**。改善した画面以外のスコアが下がっていたら、その変更は破棄する（regression-free のみ残す）。

## 停止条件

- 完了基準を達成（全画面が目標スコア以上、または本人指定の基準）
- **2周連続でスコアが上がらない**（伸び止まりとして正直に記録）
- アクセス遮断・承認が必要な変更に到達

## 禁止事項

- 経験者の目での採点（利用者は美容室スタッフ・中高年含む非IT層という前提を維持）
- スコアを上げるために基準を緩める・チェック項目を外す
- スクリーンショットなしの「改善しました」報告

## 報告形式

「画面×チェック項目のスコア表（改善前→後）／各周の変更内容／ビフォーアフターのスクリーンショット／破棄した変更とその理由／停止理由」。

## firstuser との使い分け

- **firstuser** = 初見ユーザーが**完走できるか**（導線の欠陥を探す）
- **uidesign** = 各画面が**良いか**（質を採点して上げる）
- リリース前は uidesign → firstuser の順が効率的（見た目を整えてから完走確認）
