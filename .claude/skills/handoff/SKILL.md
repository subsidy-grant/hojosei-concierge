# Handoff 引き継ぎループ

次の人間またはエージェントが**推測なしで**作業を再開できる引き継ぎ文書を作成する。

## 出力先

プロジェクト内に引き継ぎ・進捗ファイル（06_進捗.md 等）があればそこに追記。なければプロジェクト直下に `HANDOFF.md` を作成。日付見出し（絶対日付）を付ける。

## 記録する項目（すべて必須。該当なしなら「なし」と明記）

1. **現在の目標** — このセッションで何を達成しようとしていたか
2. **変更点** — 実際に変更したファイル・データ・外部状態
3. **検証済みの証拠** — 何をどう確認したか。**出所と観測時刻を付ける**（例：「22:40時点のAPI応答で〜」）。確認していないことを完了扱いにしない
4. **一次情報の取り直しコマンド** — 疑わしいときに1コマンドで現状を確認できる手段（CLAUDE.mdの規則。再開時はまずこれを実行させる）
5. **未着手の範囲** — やっていないこと。やったように見えるが未検証のもの
6. **不確実な点・リスク** — 推測で進めた箇所、時間経過で腐る可能性のある観測
7. **触ってはいけない領域** — 本番データ・課金API・削除禁止ファイル等
8. **最後の判断・関門** — 直前に下した決定と、本人確認待ちの事項

## 締め

**次の安全なアクションをちょうど1つ**指名し、「再開者が仮定してはいけないこと」を添える。

## 停止条件（厳守）

引き継ぎを書き終えたら**停止する。指名したアクションを開始しない**。引き継ぎの作成を次アクションの許可と解釈しない。

## 禁止事項

- 推測を「完了した作業」として書く
- ブロッカーや失敗の省略
- 過去の観測を時刻表記なしで現在形で書く（「〜になっている」ではなく「HH:MM時点で〜だった」）
