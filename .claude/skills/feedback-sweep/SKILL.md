# Feedback-sweep 指摘の横展開監査ループ

**1件の指摘は1件の修正で終わらせない。**同じ型の問題を全体から探して潰す（「障害を見つけたら汚染データを洗い出す」の開発版）。

## 手順

1. **指摘を収集する**。参照源：
   - このセッションと記憶にある本人からの修正指摘・差し戻し
   - メモリの feedback 系ファイル（`~/.claude/projects/.../memory/`）
   - `git log` の修正コミット（このプロジェクトはコミットメッセージに誤報・指摘の経緯が書かれている）
   - 進捗ファイル（06_進捗.md 等）の記録
   期間指定があればその範囲、なければ直近2週間目安。
2. **重複を除いた問題一覧を作り、失敗パターンに分類する**（例：「古い観測での断定」「値の更新漏れ」「非IT利用者に通じない文言」「検証せずに完了報告」）。
3. **各パターンについて現在の状態を検証する**——過去に直したものが本当に直っているかを、記憶ではなく現物で確認。
4. **プロジェクト全体を各パターンで監査する**。指摘された箇所以外に同じ型が潜んでいないかを網羅的に探す。
5. **確認できた該当箇所を修正**し、可能なら再発防止（テスト・チェックリスト・スキル改訂）を足す。
6. **全体監査を繰り返す**。新規検出ゼロになるか、指定の反復予算が尽きるまで。

## 停止条件

- 問題一覧がすべて閉じ、最終の全体監査が新規検出ゼロ（正常終了）
- 破壊的変更・本番反映・外部に見える変更が必要になった → 承認待ちとして明示して停止
- ブロック・予算切れの項目は「未解決」として正直に残す（黙って閉じない）

## 禁止事項

- 中立的な議論・雑談から「これも指摘だったはず」と欠陥を推測する（明確な指摘・差し戻しだけを種にする）
- 解決済み扱いの問題を、現在の動作確認なしに「直っている」と報告する
- 見つけた件数を増やすために指摘の定義を緩める

## 報告形式

「収集した指摘一覧（出所付き）／失敗パターン分類／パターン別の新規検出と修正（証拠付き）／再発防止に足したもの／未解決・ブロック項目」。
