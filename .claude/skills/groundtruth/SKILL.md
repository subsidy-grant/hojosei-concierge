# Groundtruth 監査ループ

対象プロジェクトを**読み取り専用**で監査する。このスキル実行中はコード・設定・データを一切変更しない（修正は監査完了後、本人の指示があってから）。

## 手順

1. 監査対象を確定する。引数がなければ現在の作業ディレクトリのプロジェクト。
2. 領域を列挙する：アーキテクチャ／セキュリティ（秘密情報の置き場所含む）／外部連携（API・Webhook・cron等）／データ整合性／運用（デプロイ・バックアップ）／ビジネスロジック。プロジェクトに存在しない領域は N/A。
3. 各領域を**フレームワークの常識や過去の記憶ではなく、いまの一次情報**（実ファイル・実コマンド・実APIの応答）で検証する。
4. 各領域に必ず次のいずれかの判定を付ける：
   - **証明済み** — 直接的な証拠あり（出所と観測時刻を添える）
   - **弱点** — 問題を確認。重大度（高/中/低）を付ける
   - **N/A** — このプロジェクトに存在しない
   - **未検証(blocked)** — アクセス不足等で確認できず。**「問題なし」と見做さない**

## 停止条件

すべての領域に判定が付いたら停止。判定なしの領域（サイレント・ギャップ）を残さない。

## 禁止事項

- コード変更（読み取り専用）
- シークレット値の本文表示（存在確認と置き場所の報告まで）
- アクセスできなかった領域を暗黙に「問題なし」扱いすること
- 前回の監査結果や自分の過去の発言を根拠にすること

## 報告形式

領域ごとに「判定｜証拠（出所＋観測時刻）｜重大度（弱点のみ）」の表。最後に弱点を重大度順に並べ、推奨する修正順序を1つ提案して終わる（修正自体は始めない）。
