# Skill-audit スキル体系の保守監査

**スキルを1つでも追加・変更・削除したら、そのターンの最後に必ず実行する。**指示を待たない。

## 手順

### 1. 実物を数える（記憶で答えない）
`~/.claude/skills` と `~/.claude/agents` のディレクトリ一覧、各リポジトリの `.claude/skills` の数を実際に取得する。

### 2. 説明文の衝突チェック
全SKILL.mdの `description` を抽出して読み合わせ、**同じ言葉で発動する2つ以上のスキル**を探す。特に：
- 同じ道具を使うもの（Playwright系、ファイル操作系）
- 同じ工程を名乗るもの（レビュー、テスト、デザイン、監査）
- 新規導入した公式スキルと自作スキルの間（**過去に穴が出たのはここ**）

衝突を見つけたら**どちらが主かの仲裁ルール**を決め、リポジトリCLAUDE.mdの「スキルの競合仲裁」節に追記する。公式スキル本体は書き換えない（更新追従とライセンスのため）。

### 3. 参照の整合性チェック
- `devflow` が呼ぶスキル名がすべて実在するか（統合・改名・削除で壊れやすい）
- 各スキル内の相互参照（「〜はuicheckが担当」等）が実体と合っているか
- リポジトリ `CLAUDE.md` のスキル一覧・個数が実物と一致するか
- メモリ（`reference_loop_library.md`、`MEMORY.md`）の記述が実体と一致するか

### 4. 同期状態チェック
5リポジトリ（beauty-subsidy-roadmap / hojosei-concierge / joseikin-navi / line-task-manager / note-diary-bot）で：
- 自作スキルに同期漏れ・削除漏れがないか
- **Proprietaryライセンスの公式スキル（xlsx/pdf/docx/pptx/doc-coauthoring）が混入していないか**（混入は撤去する）
- `git fetch` 後の status で origin と同期しているか

### 5. 使われ方の記録（棚卸し時のみ）
本人が「棚卸し」を求めた場合のみ、セッション記録（`~/.claude/projects/**/*.jsonl`）からSkill呼び出し回数を集計する。**明示的な `Skill` 呼び出しだけが数えられ、説明文経由の自動発動は計上されない**ことを報告に明記する（過小評価になる）。3か月使われていないものはRETIRE候補として挙げるが、**削除は本人の承認を得てから**。

## 停止条件

4項目（衝突・参照・同期・必要なら使用状況）すべてに結果が付いたら停止。問題ゼロなら「問題なし」と明示する（チェックしなかったのと区別するため）。

## 禁止事項

- ディレクトリ一覧やgit statusを取り直さずに「同期済みです」と書く
- 衝突を見つけて仲裁ルールを書かずに報告だけして終わる
- 本人の承認なしにスキルを削除する（追加・修正・仲裁ルール追記は承認不要）

## 報告形式

短くてよい。「スキル数（ローカル/リポジトリ）／衝突：あり（内容と決めた仲裁）orなし／参照ずれ：内容or なし／同期：OK or 直した内容」。問題がなければ2〜3行で済ませる。
